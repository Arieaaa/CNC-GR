## 1 静态核实项（已完成，附证据）

### V-01 SSF 的切换判定只有一个 0.1 dB 的算术门限

- 判定式：`if float(ref_rssi) > float(rssi + 0.1)`，`mn_wifi/associationControl.py:30-45`（第 42 行）
- 后果：SSF 分支里**没有**信号强度下限、**没有**停留时间/冷却计时；只要候选 AP 更强就 `disconnect_pexec`。
- 与本项目关系：方案 §1.2 候选一（"信号门槛＋切换冷却"）确实不在现有实现里，5号的扩展不是重复劳动。
- 汇报口径：可以说"最灵敏切换/只要更强就走"；不可以说"信号阈值切换策略"。

### V-02 LLF 内置 2 个终端的滞回，且完全不看信号

- 判定式：`if len(ap_intf.associatedStations) + 2 < ref_llf`，`associationControl.py:14-28`（第 23 行）
- 后果：候选 AP 至少要比当前 AP 少 3 个终端才切换 → LLF 臂的切换次数天然偏低，且可能把终端送到更远、信号更弱的 AP。
- 汇报口径：LLF 的收益（负载更均）与代价（RSSI 更弱、可能更远）必须成对出现，不能只报收益。

### V-03 RSSI 是模型算出的整数 dB，因此 V-01 的 0.1 dB 门限实际等价 1 dB 台阶

- 证据：`propagationModels.py:119-120` `pldb = 10*exp*log10(dist/ref_d) + xg`、`self.rssi = gains - (int(pl) + int(pldb))`
- 后果：SSF 判定在两值相等时不切换，差 1 dB 就切换。所谓"0.1 dB 迟滞"在整数 RSSI 下不起作用。
- 汇报口径：描述切换灵敏度时用"1 dB 量化台阶"。

### V-04 wmediumd 干扰配置里没有信道号字段

- 证据：`mn_wifi/wmediumdConnector.py:106-176` 写出的字段只有 `enable_interference / type="path_loss" / positions / fading_coefficient / noise_threshold / isnodeaps / tx_powers / model_name` 与模型参数。
- 后果：方案 §2.2 的"2.4 GHz 1/1 与 1/6 对比"是否真的产生干扰差异，**必须由 C-04 实测**，不能假设。
- 汇报口径：在 C-04 出结果前，实验A的信道对照一律写成"待核查"。

### V-05 默认所有接口共享同一介质；隔离需要显式划分

- 证据：`examples/wmediumd_multimedium.py:5`「By default, all interfaces share the same medium and the packet ordering takes into account all of their queues.」；隔离接口 `net.setInitialMediums(...)`（同文件 :46）
- 后果：不划介质时，两个 BSS 的队列排序互相影响；这对实验A（同/分信道）和实验C（出口队列）都是前提条件。
- 汇报口径：6号 讲 QoS 时要说明队列位于哪个接口、是否与另一介质共享。

### V-06 发射功率以 dBm 整数下发，小数被截断

- 证据：`link.py:349-356` `self.txpower = int(txpower)` → `iw dev X set txpower fixed <dBm*100>`
- 后果：参数表里写 14.5 dBm 实际生效 14；核查必须看 `iw ... info` 输出而不是脚本字面值。

### V-07 读不到 iw 时有兜底常量，不能作为配置依据

- 证据：`node.py:186-194`：`iw dev <intf> info | grep txpower`，异常时 `txpower = 14 if isinstance(self, AP) else 20`
- 后果：日志里若出现"AP 14 / 终端 20"，可能是兜底值而非真实设置；C-02 要逐口打印确认。

### V-08 无线口的速率/时延/丢包是 tc-netem 按距离公式下发的

- 证据：`link.py:75-79` `get_bw()` 用 `eval(str(custombw) + self.eqBw)`（`rate <= 0` 时兜底 0.1）；`link.py:85-92` `tc qdisc replace dev X root handle 2: netem rate ...`
- 后果：本原型里"信道变差 → 速率下降"是通过 netem 参数体现的，**不是**逐帧退避重传的结果。CSMA/CA 用来解释机理，量化证据来自 netem 与干扰模型。
- 汇报口径：2号的 PPT 会明确分栏"标准里有的"与"本次仿真里有的"。

### V-09 mode 未显式设 bw 时的默认速率表

- 证据：`link.py:207-217`；`net.py:882`（`addLink` 未给 bw → `params['bw'] = intf.getCustomRate()`）
- 数值：`getCustomRate()` a=11 / b=3 / g=11 / n=600；`getRate()` a=54 / b=11 / g=54 / n=300
- 后果：mode='g' 时若走 `getCustomRate` 分支，单接口上限可能只有 11 Mbit/s。这会成为实验A总吞吐的天花板，必须先由 C-05 确认。

### V-10 默认传播模型与默认参数

- 证据：`propagationModels.py:19-31`：`rssi=-62`、`model='logDistance'`、`exp=3`、`xg=0.0`、`sL=1`、`noise_th=-91`、`cca_threshold=-90`；`net.py:65-67` `fading_cof=0, noise_th=-91, cca_th=-90, autoAssociation=True`
- 后果：方案 §2.2 要求"统一参数表记录传播模型"；本项目直接沿用 logDistance/exp=3，并在参数表里显式写出，防止版本变更引入不同默认值。

### V-11 twoRayGround 分支把信道宽度当成了频率

- 证据：`propagationModels.py:79-101`，`f = intf.band * 1000000`，而 `band` 是信道宽度（`link.py:1300/1389/1434` `self.band = 20  # bandwidth channel`）；正确的自由空间分支 `:44-60` 用的是 `intf.freq * 10**9`
- 后果：选 twoRayGround 会得到物理上无意义的距离转折点。**决定：本项目不使用 twoRayGround**（写入参数表 X-01）。

### V-12 关联策略是挂在移动性对象上生效的

- 证据：`net.py:218-219` `if self.ac_method: mob.ac = self.ac_method`；用法 `Mininet_wifi(ac_method='ssf')`（`examples/associationControl.py:13-19`）
- 后果：不传 `ac_method` 时不会做 SSF/LLF 的重关联评估；实验B两臂必须各自单独起网，不能在同一进程里"切换策略"。
- 汇报口径：5号 讲策略时说明"策略在移动性循环里评估"。

### V-13 初始关联由距离-vs-range 门限决定

- 证据：`net.py:837-840` `dist = get_distance_to(ap); if dist > ap_intf.range: return False`；`range` 默认由 `link.py:324-326` `SetSignalRange(self).range` 反算；`setRange` 在功率不足时打印 `requested ... cannot be satisfied ...`（`link.py:300-321`）
- 后果：脚本里写 `range=` 不一定生效（受最小发射功率约束），且官方 FAQ 已把功率粒度列为已知限制（`https://mininet-wifi.github.io/faq/#q7`）。
- 汇报口径：讲"终端选 AP"时，先说本原型的准入是距离/range，再说移动后的重关联才是 SSF/LLF；两者不要混为"扫描选最强信号"。

### V-14 iperf3 的两个口径事实

- 证据：`esnet/iperf src/iperf.h:446` `#define PORT 5201`；`src/iperf_udp.c:211-232` 抖动按 RFC 1889 式递推 `sp->jitter += (d - sp->jitter) / 16.0`
- 后果：报告的 jitter 是滑动平均，不是 P95/最大值；与 P95 RTT 不同口径，7号的字段表要分开命名。
- 汇报口径：6号/8号 说"抖动"时统一注明"iperf3 报告的滑动平均抖动"。

### V-15 信道→频率映射已核实，且有两个静默失效的坑

- 证据：`mn_wifi/frequency.py:8-14` 按 mode 分派——`a/n/ac/ax5` → 5 GHz 表，`ax/be` → 6 GHz 表，其余（含 `b`/`g`）→ 2 GHz 表；`:30` 的 2 GHz 表是 `1..11 → 2.412, 2.417, ..., 2.462` GHz，与教材栅格 `2407+5n` 一致。
- 坑 1：**信道 12/13 不在表内**，而 `get_freq()` 没有兜底分支（`:15-20`），返回 `None` → `intf.freq` 为 None；该值还要进入 1 m 参考损耗计算（`propagationModels.py:44-60`），后果是覆盖圈/关联距离一起算不出来。
- 坑 2：**`mode='n'` 被归到 5 GHz 表**。若有人为了更高速率把 mode 改成 n 而仍写 `channel='1'`/'6'，信道号不在 5 GHz 名单里 → 同样返回 None。本项目固定 `mode='g'`，不为了速率改 mode（速率上限问题请走 R-15/C-05）。
- 附带：`get_freq_60ghz` 存在（`:59-64`）但分派里没有 60 GHz 分支，`mode='ad'` 实际会落到 2 GHz 表——同样不要尝试。
- 状态：**本条把 C-02 的"预期值"从推算升级为源码核实值**；实测仍要做，因为要确认脚本里的字面值真的下发到了接口。

### C-03 介质模型是否真的生效（方案 §2.2 的硬要求；4号执行，2号判定，11/8）

```bash
# 1) 距离-RSSI 单调性：把同一终端放在 10/20/30/40 m 处
sta1 iw dev wlan0 link            # 记下模型给定的信号
# 2) netem 是否按距离变化
sta1 tc -s qdisc show dev wlan0   # 期望出现 rate/latency/loss，且随位置变
# 3) 关掉 ap2 或把终端移远，丢包/RTT 应明显变化
```

- 判据：RSSI 随距离按 logDistance 下降（对数斜率 ≈ 10·exp，参数表 §7 表可对照）；netem 参数随位置更新。
- 若不满足：说明介质模型没进路径，实验A/B 的"无线"解释全部作废，回到 3号 排障。

### C-04 分信道是否带来可观测差异（4号，2号判定，11/9）

- 步骤：位置（X-07/X-08）、txpower（R-05）、bw（R-15）、方向（T-01）、时长（T-03）全部固定；只改 ap2 的 channel：`1/1` 与 `1/6` 各 3 次（12 终端档）。
- 判据：定义 `Δ = 总吞吐(1/6) − 总吞吐(1/1)`，`s = 组内重复间标准差`。
  - `Δ > 2s` → 可以写"观察到信道划分带来的吞吐差异"；
  - `|Δ| ≤ 2s` → **必须写"未观察到信道隔离收益"**，并按 V-04/V-05 解释为平台介质模型的限制；
  - 想补强可再用 `net.setInitialMediums(...)` 显式分介质复测一轮（V-05）。
- 回填：本记录 §4 风险项 R2。

### C-05 每接口速率天花板（4号 + 3号，2号判定，11/8）

- 步骤：`n=1` 单终端打满，记录总吞吐；然后不写 `bw`、写 `bw='54'`、写 `bw='100'` 各跑 3 次。
- 判据：若"不写 bw"档稳定停在约 11 Mbit/s（V-09），则默认分支取的是 `getCustomRate`；后续所有 A 组实验必须显式统一 `bw` 并写入参数表 R-15。
- 影响：这条决定"终端数增加时总吞吐是否还能上升"，也就是实验A能不能看到"共享介质饱和"。

### C-06 netem 与 tc 分类是否互相覆盖（6号 + 2号，11/9）

- 步骤：QoS 臂启动前后各执行 `tc -s qdisc show dev <intf>` 与 `tc -s class show dev <intf>`。
- 判据：`link.py:85-92` 用的是 `qdisc replace dev ... root handle 2: netem`；若 6号 的 HTB 挂在同一设备的 root 上，会发生 replace 覆盖（root 只有一个）。需要确认 6号 的分类规则在实验运行期间仍然存在并命中（class 的 `Sent` 计数增长）。
- 汇报口径：6号 讲"规则命中"的证据必须来自这条计数，而不是配置文件文本。

### C-07 回程与服务器是否留有余量（方案 §2.2；3号，11/8）

```bash
h1 iperf3 -c <server> -t 30        # 纯有线路径（不走无线）
```

- 判据：有线路径吞吐 ≥ 无线档最高值的 3 倍；否则回程是瓶颈，实验A的解释要改写成"受限于有线回程"。

### C-08 随机种子与可复现（方案 §5.2；7号 + 3号，11/10）

- 判据：同配置重复两次，位置序列/RSSI 序列完全一致（若启用 `logNormalShadowing`、`nakagami`、`setMobilityModel`，则必须显式记 `seed`；`net.py:180 self.seed = 1`）。
- 记录：种子值写入每条 run 的元数据行。

### C-09 切换是否真的发生（方案 §3.2 前置条件；5号，2号判定，11/9）

- 判据：移动终端在路线上 BSSID 变化 ≥ 1 次；SSF 臂与 LLF 臂的切换次数不同；若两臂都 0 次或都"每次都切"，则策略对照不成立，先按 V-01/V-02/V-12 检查 `ac_method` 与 range。
- 记录：切换时刻、当时位置、两侧候选 RSSI、两侧关联终端数（这 4 列缺一个就无法复算判定式）。

### C-10 探测包口径（5号 + 7号，11/9）

- 判据：日志里必须注明探测周期与超时（如 `-i 0.5 -W 1`），"中断间隔"用连续两次成功探测之间的时间表述；不得写成协议级切换耗时。
