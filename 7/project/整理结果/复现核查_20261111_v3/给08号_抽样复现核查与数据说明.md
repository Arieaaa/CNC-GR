## C 组出口队列规则

检查的是服务器仿真接口 `srv-eth0`，而非公网管理口或 Wi-Fi 空口：

- **baseline 原轮和复跑**：父类 `1:1` 的 rate/ceil 均为 2 Mbit/s；默认共享类 `1:20` 为 2 Mbit/s，bfifo 限额 32768 字节，无分类 filter。两轮各检查 60 份运行快照，结构/配置与初始及结束快照一致；最终共享类分别累计 15,146,044 和 15,127,542 字节。这表明共享类有流量，不单独证明 UDP 或 TCP 各自的分类命中。
- **额外检查的 QoS 正式轮**：[expC_qos_c2000_run02_20261109T134447Z_0439qzhl](../../原始日志/expC_qos_c2000_run02_20261109T134447Z_0439qzhl/)，并非本次复跑。父类上限 2 Mbit/s；实时类 `1:10` 的 rate 为 600 kbit/s，后台类 `1:20` 为 1400 kbit/s，ceil 均为 2 Mbit/s；两类 bfifo 限额分别为 8192、24576 字节。60 份运行快照与初始和结束配置一致。
- 该 QoS 轮的 `configured-srv-filter.txt` 包含指向 `1:10` 的 UDP 协议、源端口 5202、目的地址 `10.44.0.1` 匹配项，以及指向同类的 ICMP 和目的地址匹配项。启动实验 ping 前的实时类计数已达 98,218 字节，与运行器先启动 UDP/TCP 后启动 ping 的流程相符，支持 UDP 进入实时类的判断；这是类级计数，**不是每条 filter 的独立命中计数**。结束时实时类和后台类分别为 2,869,002、12,291,287 字节。
- 该环境 `tc -j` 导出的 filter JSON 只保留了部分 u32 match 项；若只读 JSON 会漏掉协议和端口条件。检查完整规则请使用 `configured-srv-filter.txt`，不要根据 JSON 中单个目的地址推断完整过滤条件。

QoS 轮下载时 631 个文件与服务器前后 SHA-256 一致；这次只独立检查一轮 QoS 的配置与计数，尚未逐轮复算 3 个 QoS 正式结果，也未执行 QoS 复跑。
