# 数据采集与异常检查清单 v0.1

适用于试跑、正式采集、整理交接和抽样复现。问题一律保留证据、说明影响并指派责任人；本清单用于提示检查，不取代实际脚本和原始日志。

## 采集前

- [ ] 与 3 号预约串行运行，确认采用其审核部署的入口和公共锁；记录脚本、拓扑与工具版本，保存配置。
- [ ] 写明实验、对照臂、终端数、信道、位置和实际关联、流方向、每流负载、时长、窗口及种子（适用时）。核查待比较两臂仅改变计划变量。
- [ ] 确认各指标的采集方法、端点、单位、采样间隔、时间来源和日志路径；多来源时核查时钟对齐方式。明确失败/缺测如何保留。
- [ ] 正式配置至少安排 3 次重复。60–90 s 和前 10 s 预热只是方案建议；须实际约定并记录。B 组切换事件不能按固定预热规则丢弃。
- [ ] 2 号表的 AP 位置与 SSID 和 3 号文档不一致，核对当前脚本及实际运行；传播指数、功率、链路速率、信道宽度等记录设置值和实际读取值的来源。

## 每次运行后

- [ ] 状态最终为成功还是失败、运行完整时长、操作者和原始目录均有记录；失败或未结束运行保留日志，不能按成功处理。
- [ ] 配置、状态、原始输出与版本信息可读取，`run_id` 和重复编号唯一；从整理数据能定位原始文件及行号或 JSON 路径。
- [ ] 逐流/逐终端记录数和预期对应；检查重复、缺测、日志截断、端口冲突、服务端拒绝及进程异常。缺失不补 0，真实 0 不误标缺失。
- [ ] 单位、方向、窗口和时间基准一致；窗口外样本不混入稳态统计；核查跨文件时间偏差和移动事件时间分辨率。
- [ ] 吞吐来自接收端且不重复叠加；UDP 丢包有同流同窗口分子分母；RTT 采样数与超时另记；抖动标明工具和版本。
- [ ] 观察 CPU/内存快照、极端值及重复波动；标注可能的影响并与负责人排查，不随意删除异常点或宣称异常必然由某一原因导致。

## 各组专项

### A：并发与信道

- [ ] 终端分档与信道对照的固定项一致；吞吐和 UDP 丢包若分轮，分别保留配置与运行 ID。
- [ ] 每个并发客户端有独立服务进程/端口，或已有服务端支持并发的验证；拒绝连接不算无线丢包。
- [ ] 检查实际信道及关联；信道隔离、链路速率上限和回程余量须有实际核查证据，不能预设分信道有效。

### B：移动与关联

- [ ] 对照使用同一路线、背景终端与负载；检查策略是否实际生效且确有可观测的关联变化。
- [ ] 位置、AP/BSSID、信号、各 AP 关联数和探测结果可按事件时间对齐；模型信号标为模型给定值。
- [ ] 标记前后成功探测、失败/超时、周期和超时设置；只报告可观测的连续成功探测间隔，不称协议级切换耗时。缺少前后成功探测时不计算。

### C：混合业务与 QoS

- [ ] 两臂业务方向、出口、聚合上限和负载可比，且已复现拥塞；核对业务实际经过配置的服务器仿真出口。
- [ ] 保存 `tc` 规则和前后计数，确认规则命中并排查其他队列配置覆盖。记录 UDP 实时流指标及后台 TCP 接收吞吐，不能把出口管理说成空口 EDCA。

## 复现与交接

- [ ] 3、7 号从 A、B、C 各抽至少一个正式配置；复现保存独立运行 ID、原始与复跑目录、版本/配置差异、关键指标差异及失败原因。
- [ ] 整理结果与原始日志分开，交 8 号字段字典、运行记录、原始索引、异常清单及复现记录；注明已核查与尚待核查项目。
- [ ] 与 8 号确认统计窗口、P95 算法、阈值、有效分母及失败/缺测处理；阈值未确认前不计算达标率。
