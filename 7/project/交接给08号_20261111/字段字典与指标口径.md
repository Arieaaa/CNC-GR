# 字段字典与指标口径 v0.1

状态：7 号草案，待 4–6、8 号确认；平台和无线参数由 2、3 号核查。所有字段名是建议的整理层名称，原始工具格式不必强行修改。实际参数以运行记录、脚本和设备输出为准。

## 1. 记录粒度及通用规则

- **运行记录**：每个独立运行目录一条，以 `run_id` 唯一标识；一次重跑另立记录并关联原运行。实验配置相同的多次重复分别记录，失败运行也保留。
- **流配置**：每运行、每条实际业务流一条，用 `run_id + flow_id` 关联；记录多终端、多方向、多业务时不可只写一个笼统速率。
- **时间序列**：每运行、每终端或业务流、每种指标、每个采样时点或统计区间一条。建议采用长表：`run_id + series_id + metric + time_start + time_end`；如原日志同一范围有多条，以原始记录序号区分。`series_id` 在该运行内标识终端、流、方向及来源的组合，不能把不同粒度拼成一条。
- **事件记录**：每运行、每个移动关联变化或其他关键事件一条，保存事件时间、类别、相关终端和原始来源；并列发生的事件用原始序号区分。
- 文件用 UTF-8；数值保留原精度，单位在字段定义中固定。时间优先记带 `Z` 的 UTC ISO 8601；若来源仅有相对时间，保留原值与基准，基准不明时不得伪造绝对时间。记录各来源的时钟或对时方式及可能偏差，未经验证不得假定跨日志完全同步。
- 未适用留空；适用但未采到也留空，另在缺失说明中写明原因。实际测得 0 正常填写 0。原始日志不覆盖，整理结果独立保存；每条结果需能追溯到原始文件及记录位置。
- 示例名称如 `expA_n12_ch1-6_run01` 仅为命名示例，不是现有实验结果。样例或虚构数据一律显著标为“示例”。

## 2. 运行记录字段

“必填”指所有运行需记录；“条件必填”指场景适用时记录。未能获取的必填项应登记为缺失及影响，不能以默认值冒充实测。

| 字段 | 含义、单位及填报要求 | 典型来源 |
|---|---|---|
| `run_id`、`experiment`、`run_kind` | 必填：唯一运行 ID；A/B/C；试跑、正式或复现 | 目录、记录表 |
| `operator`、`started_at_utc`、`status` | 必填：操作者、实际 UTC 开始时间、最终状态及失败原因；运行中标记未结束 | `config.json`、`status.txt`、运行日志 |
| `config_id`、`variant`、`repeat_no` | 必填：组内确定的配置标识、对照臂及重复编号；`config_id` 如何编码由 4–6、8 号确认 | 实验配置 |
| `station_count`、`ap_channels`、`traffic_direction` | 必填：终端数、各 AP 实际信道（如 `ap1=1;ap2=6`）、业务方向；混合方向按流表说明 | 配置与实际无线信息 |
| `duration_s`、`window_start_s`、`window_end_s` | 必填：计划和实际时长、相对运行起点的分析窗口，单位 s；同时记录预热及其原因。移动事件不可因预热被丢弃 | 运行日志、统计约定 |
| `script_version`、`topology_version`、`tool_versions` | 必填：实验脚本、拓扑、iperf3 等工具的版本或提交号，以及系统/内核和介质组件的可获得版本；无法确定须标缺失 | 版本文件、脚本及工具输出 |
| `raw_index`、`config_source` | 必填：原始目录和文件索引、配置文件路径及其版本；不含密码 | 运行目录 |
| `model`、`path_loss_exp`、`txpower_dbm`、`link_bw_mbps` | 传播模型/指数、各接口发射功率（dBm）、链路速率设置（Mbit/s），按接口或配置文件记录；明确实际读取值、脚本设定值或未知。`link_bw_mbps` 不等于无线信道宽度 | 配置、实际接口信息；2 号 §6 要求的 exp/功率/bw |
| `channel_width_mhz`、`positions`、`associations` | 无线信道宽度（MHz）、AP/终端位置（m）、实际关联；按接口/终端或文件引用记录。与链路速率区分 | 配置、`iw` 输出 |
| `seed`、`host_snapshot`、`notes` | 随机过程适用时记种子；建议保存 CPU/内存运行前后快照；备注异常和变更 | 配置、主机及运行日志 |
| `reproduction_of` | 复现时填原运行 ID；保存两次版本、参数和关键指标差异 | 复现记录 |

## 3. 流配置字段

| 字段 | 含义、单位及适用情况 |
|---|---|
| `run_id`、`flow_id`、`station_id` | 必填：关联运行、该运行内流编号、终端；一台终端可有多条流 |
| `protocol`、`direction`、`endpoint`、`port` | 协议、实际方向、发送/接收端和端口；记录命令及工具版本以核实反向模式 |
| `offered_rate`、`packet_size_bytes` | 发送设定速率及明确单位、UDP 包长（byte）；TCP 不适用的发送定速或包长可留空，取决于实际命令 |
| `start_offset_s`、`duration_s`、`interval_s` | 相对运行起点的启动时间、时长和报告间隔，单位 s；流起点未对齐时不可直接叠加 |
| `raw_files` | 客户端、服务端、探测等原始日志文件及来源，标记发送端/接收端 |

## 4. 时间序列与事件字段

| 字段 | 含义、单位及填报要求 |
|---|---|
| `run_id`、`series_id`、`station_id`、`flow_id` | 运行、序列、终端和适用的流 ID；非流指标的 `flow_id` 留空 |
| `time_start`、`time_end`、`time_basis` | 采样点两者相同，统计区间填起止；标明 UTC 或相对哪个起点及单位。不同时钟先说明对齐方式 |
| `metric`、`value`、`unit` | 一个指标值一行；使用下表单位。区间聚合值需注明聚合方式、采样频率或窗口 |
| `source_role`、`source_ref`、`quality_note` | 发送端/接收端/探测端等，原始文件和行号或 JSON 路径，缺测、估算、异常等说明 |
| `ap_id`、`bssid`、`rssi_model_dbm` | 适用时记录同一时刻关联 AP/BSSID 及模型给定信号强度 dBm；分别保留来源和时间，缺测不推断 |
| 事件：`event_id`、`event_time`、`event_type`、`station_id`、`before`、`after`、`source_ref` | B 组记录关联变化、路线和探测相关事件；若只知区间而非准确时刻，保存区间和时间分辨率 |

## 5. 指标统一定义

| 指标 | 定义、单位及注意事项 |
|---|---|
| 吞吐量 | 接收端单位时间有效接收的数据量，Mbit/s；区分每终端、每流和总量，并记录协议、方向、接收端和窗口。汇总只相加同一时间窗口内独立流的接收吞吐，不能把发送端和接收端重复相加。 |
| RTT | 探测包往返时间，ms；保留逐次结果，按约定窗口计算均值及 P95，明确样本数和 P95 算法；超时、丢失不填作 0。 |
| UDP 丢包 | 同一流、同一窗口按工具报告的丢失包数 / 发送包数 × 100%，记录分子、分母、发送速率、包长和来源；分母为 0 或未知时不计算，记录缺失。不同工具口径及重排处理待核实。 |
| UDP 抖动 | 按 iperf3 等实际工具的 UDP 接收报告，单位 ms；保留工具版本、来源和窗口，不与 RTT P95 混称。 |
| 业务中断间隔 | B 组切换附近连续两次成功探测的时间差，单位 ms；保留两次成功时间、期间失败/超时、探测周期和超时。它包括正常探测间隔，受采样分辨率约束，不等于协议级切换耗时或真实通话中断。若未观测到前后两次成功探测，则不能计算该间隔。 |
| 服务达标率 | 满足团队预先确认的服务标准的运行数或窗口数 / 有效运行数或窗口数；需先确认阈值、窗口、分母及失败/缺测处理。方案中 P95 RTT <50 ms、UDP 丢包率 <1% 只是示例，未确认为本组标准。 |

## 6. 需由各实验补充的证据

- **A**：4/8/12 终端、1/1 与 1/6 分组；位置、关联、逐流强度、持续时间及方向；吞吐和定速 UDP 丢包是否分轮；独立端口/服务进程或经验证的并发能力，保留连接失败日志。
- **B**：路线、每次位置和时间、实际 AP/BSSID、各 AP 关联数量、模型信号、背景流量；SSF/LLF 生效证据、探测结果、周期和超时。切换是否发生先经试跑验证。
- **C**：下行业务的实际经过接口、UDP/TCP 各流负载、两臂总带宽上限及持续时间；保存 `tc` 分类/队列配置和运行前后计数、规则命中、UDP 丢包/抖动、RTT 与后台 TCP 接收吞吐。计数差需有前后同口径快照。
- 对照条件不一致、失败及异常值均保留并记录，不得静默删除；正式配置至少重复 3 次，按配置和运行分别索引。
