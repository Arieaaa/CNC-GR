## 03 号接入步骤

1. 核对公共拓扑函数签名、接口名、Mininet-WiFi 安装版本及该版本关联控制代码。在初始化移动机制时传入对应策略。保存生效配置和策略调用记录，确认手动更新位置时触发已配置的控制器。禁止手工指定目标 BSSID 来制造切换。
2. 使用同一运行锁串行建网、启动背景流、采集和清理。确认起点实际关联、映射两 AP 的 BSSID，并核对每个后台流有接收数据。
3. 在拓扑已启动、背景流稳定后调用 collect(sta1, [ap1, ap2], run_dir / 'observations')。由公共入口在 finally 中停止背景流并清理拓扑。每次新建运行目录，记录策略、版本、UTC、操作者、重复编号、运行状态和异常。脚本从节点参数读取实际无线接口名。
4. 试跑要在重叠区检查两种策略是否参与决策。仅在原 AP 超出范围之后换 AP，只能证明发生重关联。若控制器没有参与或后台分布错误，保留诊断日志并修正后重新试跑。

## 07、08 号日志口径

samples.csv 保存从起点算起的单调时钟秒数、每次采样起止、位置、实际 BSSID、已连接链路信号 dBm 和两 AP 的站点数。iw.jsonl 保存每条命令、返回码、采样时间和原文。一次采样中的三次读取依次执行。空 BSSID 表示该次读取未识别到关联，以原文区分断联和解析异常。

画时间线时以相邻的最后旧 BSSID、首次新 BSSID 样本界定切换窗口，中间空样本单独标出。标记最后旧关联和首次新关联的采样时刻，下方叠加回包 RTT 和缺包序号。ping -D 使用 Unix 时间，减去 clock.json 的 epoch 得到相对秒；核查主机系统时钟无跳变。按实际时间戳报告采样间隔和可能漏掉的短事件。

从 ping.txt 找窗口前最后成功回包和窗口后首个成功回包并报告间隔，同时检查窗口内有无成功回复；如有，逐一展示相邻成功回包的实际间隔。核查 -O 提示后是否迟到，按最终序号核对丢失。缺任一侧成功样本则留空。成功间隔包含正常发包间距。逐轮列切换位置、次数、事件附近成功间隔、丢包、RTT 均值及 P95；说明窗口与 P95 算法，再汇总重复间波动。达标阈值待组内确认。
