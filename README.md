# CNC-GR

针对研究生课程计算机与网络通信的课程小组汇报仓库。

## 目录结构

每位成员使用一个编号文件夹（`1/` 至 `10/`），各自的分工资料统一放在本人编号目录下：

```text
.
├── 1/
│   ├── project/   # 本人负责的数据、文档、代码与过程材料
│   └── ppt/       # 本人完成的汇报 PPT
├── 2/
│   ├── project/
│   └── ppt/
├── ...
└── 10/
    ├── project/
    └── ppt/
```

## 协作规范

1. **按编号归档**：每位成员只在自己编号的文件夹内新增和修改内容，不随意改动他人目录。
2. **资料放 `project/`**：数据、文档、代码、笔记、参考资料等过程性材料，统一放在本人编号下的 `project/` 中。
3. **PPT 放 `ppt/`**：完成的汇报 PPT（含最终版及必要素材）统一放在本人编号下的 `ppt/` 中。
4. **规范命名**：文件名建议采用“主题_版本_日期”的形式，避免使用“最终版”“最新版”等无法区分的名称；提交前删除无关的临时文件。
5. **提交前检查**：提交前先执行 `git status`，确认改动仅涉及本人目录；提交信息建议写明编号和内容，例如 `[3] 完成第三章数据整理`。
6. **同步后再推送**：推送前先执行 `git pull --rebase origin main`，及时处理冲突，避免覆盖他人提交；不要使用强制推送改写公共历史。
7. **大文件管理**：不要直接提交超大原始数据、视频或缓存文件；可将大文件存放在网盘，并在本人 `project/` 下保留说明和访问链接。
8. **保留占位文件**：目录中的 `.gitkeep` 仅用于让 Git 跟踪空文件夹，请勿删除。

完成个人材料后，请及时提交并推送到 `main` 分支，保持仓库内容最新。

### 1 项目目标与任务范围

本项目面向教学楼内资料下载、实时音视频和移动终端并存的场景，研究怎样在无线资源有限、终端位置变化时提供可接受的网络服务。以小型仿真原型验证信道规划、接入选择和业务保障思路，为理解校园组网与配置取舍提供依据。

推荐汇报题目：面向校园多业务场景的无线网络服务保障与优化。定位为课程工程原型与可行性研究，目标是在能力和时间范围内取得可核查的验证结果；正式部署适用性仍需实网评估。

| **业务或课程目标** | **验证与工程思路** | **主要证据** |
|:--:|----|----|
| 密集终端共享资源 | 通过并发与信道对照研究教室资源配置 | 实验A吞吐量与RTT曲线 |
| 移动业务连续性 | 研究终端移动时的关联选择与中断代价 | 实验B关联与业务时间线 |
| 拥塞时保护实时业务 | 比较流量分类和带宽保障的效果及代价 | 实验C丢包率与抖动图 |
| 明确服务能力边界 | 按约定指标归纳当前配置的达标条件 | 目标达成表与局限说明 |
| 联系无线网络前沿 | 关联MLO、高可靠性与AI辅助运维 | 来源、尝试记录与展望页 |

#### 应用价值与验证范围

本项目力求提供三类认识：密集接入时如何配置资源，移动时如何权衡信号与负载，拥塞时如何分配业务优先级。仿真结论可形成后续设计与测试的参考，但真实校园部署还取决于现场覆盖、硬件、认证、回程容量和运维条件。

项目验收关注原型、可核查结果和解释质量。示例服务阈值是本组约定，达标不等于真实语音或视频体验已获得保障；若使用合成UDP/TCP业务，需说明尚未测量实际应用体验。

### 2 系统架构与实施路径

#### 2.1 实验平台与网络组成

采用 Linux 环境下的 Mininet-WiFi 与 Python 搭建网络，配置 wmediumd 干扰模式，使用 iperf3 和 ping 生成流量并采集数据。固定平台版本与配置，优先使用项目官方示例逐步修改。[1–4]

| **组件** | **建议配置**                  | **作用**                        |
|:--------:|-------------------------------|---------------------------------|
| 实验主机 | 1台运行Linux的电脑或虚拟机    | 统一执行实验，记录CPU和内存负载 |
|  无线AP  | 2个，位置固定，覆盖区部分重叠 | 模拟教室与走廊相邻区域          |
| 无线终端 | 4、8、12个，选1个作为移动终端 | 改变并发规模并测试移动接入      |
| 有线网络 | 1个交换节点与1个业务服务器    | 连接两个AP，提供共同业务目的端  |
| 实时业务 | 周期性小流量UDP               | 模拟交互或语音类业务            |
| 后台业务 | 持续TCP数据流                 | 模拟下载并制造竞争              |

数据路径：终端通过无线链路接入AP，AP通过有线交换节点到达服务器。两个AP接入同一业务子网，移动实验中终端保持IP不变，避免把三层地址变更混入无线切换问题。

#### 2.2 参数与接口约定

统一参数表需记录无线制式、频段、20 MHz信道宽度、信道号、发射功率、传播模型、AP位置、终端位置与移动路线。同信道与分信道对比可从2.4 GHz的1/1与1/6配置起步；先验证介质模型和配置确实生效。

并发业务默认使用同一方向，建议终端向服务器发送；QoS实验可统一采用服务器向终端发送。每组实验记录方向，组内对照不得改变。服务器与有线回程应留有余量，避免其成为无线实验的瓶颈。

#### 2.3 搭建顺序与阶段验收

第一步：跑通1个AP与2个终端的连通性和吞吐量测试。第二步：扩展为双AP与服务器，验证终端关联和业务路径。第三步：加入终端数量、信道、移动与业务配置。第四步：4至6号采集正式数据，7号核查日志，8号统一绘图，9号集成演示；3号与7号组织抽样复现，10号梳理目标证据及前沿联系。

第一天验收：两个AP、至少两个终端与服务器能够通信，保存一组可解释的吞吐量日志。环境未通过验收时，先集中解决公共平台问题。

### 3 业务目标与三组验证设计

#### 3.1 密集接入资源配置与实验A

负责人：4号，3号提供基础拓扑，2号核查无线参数。先在同一配置下测试4、8、12个终端，保持每终端业务强度不变；再固定为12个终端，对比双AP同信道与分信道。除目标变量外，位置、AP关联、业务方向和运行时间保持一致。

记录总吞吐量、各终端吞吐量、RTT和UDP丢包率。吞吐量测试与定速UDP丢包测试可分轮进行，避免混用负载条件。输出终端数与性能曲线，以及同信道和分信道对比图。

工程解释：说明资源配置对教室密集接入的参考价值，哪些负载下达标，改善是否受竞争、回程或负载分布限制；不直接推算真实校园可承载人数。

#### 3.2 移动业务连续性与实验B

负责人：5号。固定背景终端数量和流量，让1个终端沿同一条路线从AP1区域移动到AP2区域。对比最强信号优先SSF与最少负载优先LLF，检查所用版本的具体行为。[3]

记录位置、时间、关联AP、可获得的信号强度、各AP关联终端数，以及连续探测包的收发情况。输出移动关联时间线和切换期间RTT或丢包图。需要提前验证切换真实发生，背景终端布置足以体现两种策略的差异。

工程解释：讨论何种接入策略有利于移动连续性及其代价。关联数只是负载代理；以切换附近成功探测的间隔描述中断并报告探测周期，不将其等同于协议级切换耗时或实际通话中断。

#### 3.3 实时业务服务保障与实验C

负责人：6号。同时运行小流量实时UDP与后台TCP，使用端口区分业务。在相同出口、相同总带宽上限和相同业务负载下，对比默认队列与tc分类及HTB带宽保障。[5]

建议在业务实际经过的服务器出口实施队列管理，清楚标注位置。先确定一个可复现的拥塞条件，再做正式对照。两组实验保持相同聚合速率限制；检查队列计数器，确认分类和保障规则命中。

工程解释：用UDP丢包、抖动、RTT和后台TCP吞吐量说明资源取舍，联系实时通信保障。此处验证出口管理，不能据此宣称实现空口EDCA调度或真实视频体验提升。

### 5 测量规范与验收标准

#### 5.1 指标口径

| **指标** | **统一定义与用途** | **记录要求** |
|:--:|----|----|
| 吞吐量 | 接收端单位时间实际接收的有效数据量 | 区分总量与每终端值，单位Mbit/s |
| RTT | 探测包的往返时延 | 记录平均值及P95，单位ms |
| UDP丢包率 | 以发送包与接收包数量计算的丢失比例 | 记录发送速率、包长和测试窗口 |
| 抖动 | 使用测试工具报告的UDP时延变化指标 | 注明工具及版本，单位ms |
| 业务中断间隔 | 切换附近连续成功探测之间的时间间隔 | 同时注明探测周期与超时设置 |
| 服务达标率 | 满足预设服务标准的运行或窗口占比 | 明确统计窗口、阈值与判定规则 |

#### 5.2 重复实验与数据管理

每种配置至少重复3次，每次建议60至90秒；统一预热时间，例如前10秒不计入稳态统计。移动实验按事件时间对齐，不能把切换事件当作预热丢弃。对随机过程记录随机种子，并在不同策略间使用相同的一组种子。

每条运行记录包含实验编号、策略、终端数、信道、业务方向、各流发送速率、包长、运行时长、重复编号与软件版本。时间序列至少包含时间戳、终端、关联AP、吞吐量、RTT、丢包和抖动；不适用字段留空，不用0代替。

文件名按实验、配置与重复编号区分，例如 expA_n12_ch1-6_run01。原始日志保留不覆盖；汇总图注明重复次数，展示均值及波动。iperf3并发业务需使用独立服务进程及端口，或经验证支持并发的配置，不能把服务器拒绝连接计为无线丢包。

#### 5.3 稳定运行边界与项目验收

正式采集前固定服务标准。例如，可把P95 RTT低于50 ms、UDP丢包率低于1%作为本课堂实验的示例门槛，实际阈值由组内依据模拟业务确定。这是实验约定，不是通用Wi-Fi标准。

逐一标注终端数、流量、移动及策略条件是否达标。若所有条件均达标或均不达标，只能报告当前扫描范围，不能推断容量上限；有余力再增加负载点寻找边界。

验收要求：公共拓扑可运行；三组对照均有配置与原始日志；正式条件重复至少3次；图表可由汇总脚本生成；3号与7号组织每组至少1个配置的抽样复现；十人PPT齐全；完整彩排的有效主讲时间不少于100分钟、目标110分钟；演示视频可离线播放。

### 6.2 第1至5位成员讲解提纲

下列分段均合计11分钟。按解释问题、展示证据、说明取舍的顺序准备，实际结果在实验完成后填入；不要预设优化一定有效。

#### 1号 需求与总体设计

2分钟介绍教学楼多业务场景；3分钟解释期望的资源配置、移动连续性和实时服务目标；3分钟说明架构与技术选择；2分钟讲验证、扩展与前沿三个层次；1分钟说明本项目的能力范围。

材料：场景示意图、需求对应表、架构图、实验总览。重点解释每个模块为何存在，避免逐条朗读任务分工。

#### 2号 无线原理与参数

3分钟用两个终端争用信道的例子解释CSMA/CA；2分钟说明同频竞争与信道规划；2分钟解释距离、信号与移动关联；3分钟逐项说明统一参数如何影响三组实验；1分钟总结原理与实验的关系。

材料：竞争时序图、同信道与分信道示意图、覆盖重叠图、参数表。已有机制与本项目实际实现应分别标明。

#### 3号 业务架构与原型

2分钟说明业务需求如何转成架构；3分钟解释双AP、回程与子网选择；3分钟用关键实现与路径说明原型；2分钟展示连通性和复现证据；1分钟说明模型与资源限制。

材料：环境清单、拓扑图、少量关键代码、验证日志。使用截图或预录片段说明配置，不把安装和程序等待当作讲解内容。

#### 4号 实验A 并发接入与信道规划

2分钟提出教室密集接入目标；2分钟说明并发和信道对照；3分钟解读性能及达标情况；3分钟分析配置取舍和瓶颈；1分钟说明对后续资源规划的启示及适用范围。

材料：变量控制表、终端数曲线、信道对比图、一个原始运行案例。解释曲线变化及异常点，原始结果无提升时也保留。

#### 5号 实验B 移动与AP关联策略

2分钟提出移动终端的业务连续性目标；2分钟解释路线及关联策略；3分钟解读中断与性能证据；3分钟讨论信号、负载、切换取舍及可选防抖尝试；1分钟说明当前验证范围。

材料：移动路线图、策略示意、AP关联日志、切换附近的探测记录。区分观测到的业务中断间隔与协议级切换耗时。

### 6.3 第6至10位成员讲解提纲

#### 6号 混合业务与QoS保障

2分钟解释实时通信与下载并存的目标；3分钟说明拥塞与资源分配方案；3分钟解读对照结果；2分钟说明业务保护的代价和可选调整尝试；1分钟交代合成流量与出口管理的验证边界。

材料：业务流图、分类及队列配置、规则命中记录、对比图。明确总速率上限相同，避免把出口队列管理讲成无线空口调度。

#### 7号 业务观测与证据质量

2分钟把服务目标对应到指标；3分钟解释观测、采集与可选异常提示；3分钟用原始日志定位一项服务变化；2分钟说明数据质量和联合复现；1分钟说明监测结果不能替代真实应用体验。

材料：采集流程、字段表、原始日志、清洗前后样例。重点讲数据怎样取得；三组实验的结论由4至6号及8号展开。

#### 8号 目标达成与适用边界

2分钟说明目标判据与统计口径；3分钟比较三组验证的收益和代价；3分钟解读达标条件与扩展尝试结果；2分钟说明波动和扫描范围；1分钟交接目标证据总览。

材料：汇总表、均值及波动图、达标条件表、边界案例。用已有的达标或不达标案例解释判定；未观察到边界时如实说明，不预设必须出现两种结果。

#### 9号 系统集成与演示

2分钟说明演示对应的业务目标；2分钟解释原型配置与运行准备；4分钟展示并发、移动或业务保护的可运行片段；2分钟把现象对应到观测证据；1分钟交代演示范围与备用路径。

材料：操作清单、演示脚本、完整录屏及结果截图。备用视频与现场步骤等价替换，不重复计时；展示期间持续解释观测现象，避免无解说等待。

#### 10号 工程目标总结与前沿展望

1分钟回顾三类业务目标；2分钟总结有证据的工程认识；2分钟说明完成状态、局限与正式应用前的验证条件；5分钟联系MLO、高可靠性和AI辅助运维三个前沿方向；1分钟收束全组汇报。

材料：目标与证据表、轻量扩展尝试记录、前沿来源及机制图。说明本周做到了什么、尝试了什么、还需研究什么；不承诺正式应用。此段合计11分钟，教师提问另计。

#### 6.4 彩排与计时验收

1号记录每人的有效主讲时长和累计值；完整彩排目标110分钟，验收下限100分钟。短于10分钟的成员补讲代码、日志或案例并复测。预备每人1至2分钟有实质内容的备用材料；正式汇报不依赖额外问答补足时长。

### 7 工程价值与无线网络前沿

#### 7.1 回到业务目标总结证据

10号综合1号提出的目标与4至8号提供的证据，说明三类问题在当前配置下的表现。结论使用条件化表述，例如在所测终端数、业务量和移动路线下观察到某项变化；数值由正式日志填写，不提前写成已实现的提升。

| **业务目标** | **当前原型可提供的证据** | **应用认识与剩余条件** |
|:--:|----|----|
| 资源合理配置 | 终端数、信道与吞吐量及RTT的对应关系 | 支持讨论教室资源取舍；实网容量需现场与硬件测试 |
| 移动业务连续性 | AP关联、中断间隔与切换频率的对照 | 支持比较接入选择；通话体验与认证过程需进一步验证 |
| 实时业务保护 | UDP指标与后台TCP吞吐量的变化 | 支持解释带宽分配；真实应用体验需端到端测量 |

#### 7.2 从现有问题联系前沿

Wi-Fi 7 MLO：面向单链路受干扰或性能下降的问题，多链路操作可利用链路组合或切换改善性能与连接灵活性。[6] 本组双AP漫游不等于MLO；本周以机制图和问题对应分析为主，只有取得兼容设备或可信模型后才考虑后续验证。

Wi-Fi 8高可靠性：IEEE 802.11bn正在制定，关注高可靠性、尾部时延和特定场景丢包等问题。[7] 可与本组P95 RTT、丢包及移动连续性讨论联系，但应用层RTT并不等于标准所定义的时延指标，不据此宣称实现Wi-Fi 8能力。

AI辅助无线运维：已有网络分析系统将机器学习用于基线、异常检测和故障诊断。[8] 本组可先尝试日志观测或简单阈值提示，形成采集、判断、验证的基础流程。规则监测是工程起点；模型训练、在线决策和自动回滚仍是后续研究。

#### 7.3 目标与实现状态的报告方式

统一使用状态表：已实现需附脚本或日志；已验证需附条件与结果；已尝试但未完成需附过程、原因与下一步；尚未实施列为后续研究。展望应说明所需数据、设备、接口和评价方法，避免把技术名称直接列为功能。

本项目旨在形成课程原型、可解释证据和后续研究路径。团队在时间与能力范围内推进目标与扩展，不保证最终工程能够在真实校园正式应用；正式应用需另行完成实网、规模、兼容性和稳定性评估。

### 8 交付清单与汇报说明

#### 8.1 项目交付与业务演示

交付基础拓扑与环境说明、三组配置和日志、分析绘图脚本、目标达成表、可选扩展尝试记录、最终PPT及操作清单。3号与7号组织抽样复现，10号提供前沿资料与完成状态总结；9号准备约4分钟带解说演示及等价备用视频。

演示先说明业务问题，再展示可运行现象并解释对应指标。性能结论引用正式重复实验；仅有合成流量时不宣称实际音视频体验已改善。扩展未完成时展示已有过程与限制，核心验证继续承担主要证据。

#### 8.2 实施问题的处理

优先保障公共环境、核心数据与复现。资源不足时降低终端数并记录条件；策略未改善时检查配置与瓶颈并保留结果；轻量扩展超出时间时冻结状态并说明原因。按原定110分钟准备，使用案例、原理和证据解释支撑内容。

#### 8.3 可发送到小组群的分工说明

我们以校园多业务无线网络服务保障为目标，研究密集接入、移动连续性和实时业务保护，用三组对照提供证据。1号统筹目标和PPT，2号负责原理参数，3号负责架构原型，4至6号负责三组验证，7号负责业务观测与日志，8号分析目标达成和边界，9号集成演示，10号总结工程价值并展望前沿。3号与7号联合组织复现；核心稳定后选一项轻量扩展尽力尝试，按实际状态报告，不承诺正式应用。每人11分钟，共110分钟，正式内容不少于100分钟。
