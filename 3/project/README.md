## 架构与参数

数据路径为 `sta → ap1/ap2 → s1 → srv`。双 AP 用于信道和移动接入对照；两个 AP 经同一交换机连接同一业务服务器，终端在同一业务子网内保持静态 IP。业务服务器的仿真出口供实验 C 配置队列。

| 参数 | 当前基础配置 |
| --- | --- |
| 实验机 | Ubuntu 24.04.4 LTS，部署记录中的内核为 6.8.0-138-generic，2 vCPU、约 1.9 GiB 内存 |
| 仿真平台 | Mininet-WiFi 2.7、wmediumd interference、mac80211_hwsim、Open vSwitch |
| 无线 | 802.11g、2.4 GHz、20 MHz，SSID `campus-lab`，信道 1/6 或 1/1 |
| AP 位置 | ap1 `(15,25,0)`，ap2 `(70,25,0)`，单位 m，配置半径各 36 m |
| 传播模型 | logDistance，指数 3 |
| 地址 | `staN = 10.44.0.N/24`，`srv = 10.44.0.100/24` |
| 互斥锁 | `/var/lib/wifi-lab/run.lock` |
| 原始日志位置 | 实验机 `/var/lib/wifi-lab/runs/` |

## 部署和基础验收

在已安装 Mininet-WiFi 及依赖的专用 Ubuntu 实验机上，从本目录进入脚本目录执行：

```bash
cd wifi-lab
sudo bash deploy.sh
sudo /usr/local/sbin/wifi-lab 2 1,6
```

完整重建及版本固定步骤见部署记录；实际软件版本文件为实验机上的 `/opt/wifi-lab/source-versions.txt`。每次运行打印独立日志目录，检查 `status.txt`、`config.json`、AP 信道和终端关联、ping 及 iperf3 原始输出。

基础验收为每台终端发送 3 个 ping，并让 sta1、sta2 依次各运行 3 秒 TCP iperf3。它用于检查平台数据路径；正式并发、移动和 QoS 结论由 4–6 号的对照实验产生。
